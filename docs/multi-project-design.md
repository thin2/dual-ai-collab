# 多项目管理：第一版设计与实现

## 已确认范围

统一 Web 工作簿登记并管理现有项目，保留纸张配色。网页不提供设计追问，不集成 grill-me，不在后台启动模型 CLI。开发中的设计讨论直接在当前对话完成。

第一版包含项目登记、选择、任务列表与详情、状态更新、项目级聚合统计和历史查询。跨项目依赖、归档、模板与跨项目调度不在本版范围。

## 项目登记

不要求将仓库移动到统一目录。默认项目是工具仓库（ID 为 `default`），其他项目由注册表记录稳定 ID、名称和规范化绝对路径。

注册表默认位于工具仓库 `.dual-ai-collab/projects.json`，支持 `DUAL_AI_PROJECTS_FILE` 指定绝对路径。写入使用文件锁与原子替换，拒绝重复真实路径；损坏配置报错，不自动覆盖。项目不存在时保留登记记录并标记不可用。

新目录可以登记但不会自动初始化任务板。任务板的 JSON 与 Markdown、运行数据目录不能通过符号链接跨出项目根目录。

## 项目上下文与隔离

`ProjectContext` 显式携带项目 ID、名称和根路径，解析任务文件、历史与运行数据路径。Web 每个请求根据 URL 中的项目 ID 选择上下文，没有可被另一个浏览器标签改变的全局“当前项目”，不使用 `os.chdir()`。

任务身份是 `(project_id, task_id)`。任务更新锁位于目标任务板旁；运行记录按显式项目根目录读取。同号任务可以在不同项目中独立查询和更新。

现有执行 worker 保持项目内 CLI 工作流；本版没有新增 Web 启动、停止或调度执行器的接口。以后增加执行控制时必须继续传递项目上下文，不能只传任务编号。

## 路由与界面

```text
GET  /api/projects
POST /api/projects
GET  /api/projects/{id}/tasks
GET  /api/projects/{id}/tasks/{tid}
PUT  /api/projects/{id}/tasks/{tid}
GET  /api/projects/{id}/board
GET  /api/projects/{id}/history

/project/{id}/tasks
/project/{id}/task/{tid}
```

原无项目前缀的接口保留为默认项目别名。页面顶部使用一个项目选择器和可展开的登记表单，不新增侧栏。进入详情、刷新和返回列表均保持项目归属。

Web 与 CLI 共用任务面板聚合逻辑。完成统计以有效集成确认计数；历史 DONE / VERIFIED 不直接算完成。面板 API 同时返回执行、验收、审查、集成和阻塞信息。网页手动修改状态仍不能代替审查或集成凭据。

## 验收重点

- 两个项目同时拥有任务 001，任务、运行记录、历史和更新互不串扰。
- 并发请求不改变服务进程 cwd，不在无关工作目录写运行数据。
- 注册表重启后恢复，重复路径（含符号链接别名）拒绝登记。
- 未登记项目返回 404，丢失目录返回 409；空项目只读查询不创建文件。
- 项目详情和返回链接携带正确 ID；不出现 grill-me 入口。
- 已完成计数与 CLI 的集成确认规则一致。
